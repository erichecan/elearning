3循证研究核心结论

证据分四档：🟢 强证据 🟡 有限 🔵 共识 ⚪ 商业实践。完整正文见 AAC_RESEARCH_EVIDENCE_2026-06.md。

最强、可操作的几条

  • 🟢 AAC 不会阻碍口语发展，多数研究显示口语反而有适度提升（Millar 2006 / Yuan 2024）。
  • 🟢 固定符号位置利于运动规划（Thistle 2018 / LAMP）—— 这是本项目最重要的设计约束。
  • 🟢 VSD（视觉场景）是 3-8 岁自闭症幼儿的循证实践（Patenaude 2025）。
  • 🟢 AAC 嵌入自然情境教学效果更好 → flashcard 不能孤立刷卡（Pope 2024 / Chazin 2021）。
  • 🔵 无年龄/先决技能门槛（ASHA）；起步 Universal Core 36 词、健壮词汇始终可见。
  • ⚠️ 「核心词占 80%」原始出处是 Vanderheiden & Kelso 1987（非 ASHA，原 BRIEF 归错）。
  • ⚪ Fitzgerald 配色是行业惯例、无疗效证据；一致性比配色方案本身重要。

5差距分析（需求 vs 现状）

核心 AAC 与循证约束已生产级（7/8 达标）；真正的缺口集中在安全、几个闭环、独立家长端。

🔴 安全（Phase C）—— 上线 blocker，目前几乎为零

  • 无 JWT 登录态（users 表已建但未接）
  • ADMIN_TOKEN 未设则全裸奔（if(!token) next()）
  • 无权限隔离：caregiver_child 表设计了但不用，child_id 前端可任意传 → 能看别人孩子数据（违反 COPPA）

🟠 闭环（Phase B）—— 框架在、细节断

  • flashcard「加词板」（A3，代码就绪待联调）
  • 任务 Focus：focus-data.ts 仅 62 行，步骤推进/完成回写未通
  • math / 绘本：AI 生成与审核流不完整

🔵 完整度（Phase D / 优化）

  • 无独立家长端（现全混在 admin web，无移动适配/权限）
  • 治疗师端指标粗糙，缺 ABC 行为报表
  • 原型的「core + 情境词双列」fringe 区未实现
  • 离线（无 Service Worker）、媒体加密未做
📌 盘点中纠正了 3 处 agent 误判：① flashcards 没有 vocab_id（需新增）② users 表 已建于 001 ③ BulkImportWizard 的 supabase 已清除。

7复盘（Retrospective）

✅ 做得好的

  • 循证驱动：先做真实研究再改代码，避免拍脑袋设计
  • 安全把关：提交前拦下数据库密码/API key，没让密钥进公开仓库
  • 意外收获：修 Phase A 时发现并修复了让项目编译失败的历史遗留，build 恢复绿
  • 复用优先：发现核心 AAC 已生产级，改造而非重写，省大量工作
  • 核对而非轻信：纠正了自动盘点的 3 处误判

⚠️ 踩的坑 / 发现的问题

  • 项目藏在非默认分支，导致一度「找不回」「看不到」
  • 密钥曾被提交到公开历史（根 .env 的 Supabase key）——历史遗留风险
  • 动态词区实时重排违反运动规划循证——这是个隐蔽但关键的设计缺陷
  • 数据库密码失效，阻断一切本地联调（外部 blocker）
  • 鉴权几乎为零，离上线安全底线差距大

💡 经验沉淀

  • 研究结论一律标四档可信度，不把商业实践当强证据
  • 引用要溯源（80% → Vanderheiden & Kelso 1987，纠正了二手归因）
  • 改造前先全量盘点 + gap 分析，把「需求 vs 现状」量化
  • 每个 Phase build/类型先绿再进下一步；联调依赖外部资源时，先把可验证的代码做扎实
  • 公开仓库提交前固定做密钥自检

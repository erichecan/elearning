Audrey 2.0 · 整体运行逻辑 & 用户行为流程

面向自闭症儿童的 AAC 沟通与生活辅助 App。本图把循证研究（见 AAC_RESEARCH_EVIDENCE_2026-06.md）的关键约束直接标注在流程节点上，作为反向落 PRD 的依据。绿色描边节点 = 有强循证约束、不可妥协的设计点。

① 整体运行逻辑

三端（家长 / 儿童 / 治疗师）围绕一个以儿童为中心的数据层运转，形成「配置 → 运行 → 埋点 → 分析 → 个体化回调」的闭环。

运行逻辑文字版：
  1. 配置（家长端 Mobile）：建立儿童档案与能力/偏好，上传 at home / at school 场景照片并设 VSD 热区，维护词库（core / context / custom），创建日程任务、奖励规则，审核 AI 生成的 flashcard / 绘本 / 数学题。
  2. 落库：全部写入 Neon Postgres，作为儿童端运行时的唯一数据源。
  3. 运行（儿童端 Tablet）：首页加载固定位置的核心词网格 + 句子条 + 场景入口 + 任务提醒 + 代币。孩子逐词造句 → TTS 发声；AI 仅高亮推荐、绝不挪动词的位置；切换场景只换 fringe 词与 VSD 背景，核心网格保持不变；flashcard 与 AAC 共用同一套词条，学完即可在句子条用出来；完成任务/正确沟通触发代币。
  4. 埋点：所有交互写入 analytics_events / abc_logs。
  5. 分析与回调（治疗师端 Web）：看 AAC 使用频率、独立沟通率、任务完成率与 ABC 报表，据此个体化调整词库与日程，回写数据层，闭环。

② 用户行为（用户旅程）

以孩子的一天为主线，叠加家长（夜间配置/审核）与治疗师（周期性复盘）两条支线。重点呈现「想表达 → 用固定网格找词 → 拼句发声 → 大人回应示范」这条核心沟通回路。

用户行为文字版：
  1. 孩子·沟通回路：产生表达意图 → 在熟悉的固定位置凭运动记忆找词 → 点选进句子条 → 朗读 → 沟通伙伴（家长/老师）辅助语言示范（边说边点）回应 → 强化。
  2. 孩子·场景：去学校/在家切换场景 → 相关情境词与场景图浮现（核心词位置不变）。
  3. 孩子·任务：收到任务提醒 → 进入 Focus 模式（视觉计时 + 步骤）→ 完成 → 获代币 → 兑换。
  4. 孩子·学习：进入 flashcard/数学 → 学新词 → 回到沟通场景用出来（学用一体，非孤立刷卡）。
  5. 家长·支线：夜间上传场景照片、调词库、审核 AI 内容、看孩子当天表现。
  6. 治疗师·支线：每周看数据看板与 ABC 报表 → 个体化调整目标词与日程。
